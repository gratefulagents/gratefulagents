## What an automated protocol-specific workflow can rely on

Global blocker first: this sandbox has node / yarn / pnpm / cargo but **no `forge`, `anvil`, `dapp`, `hevm`, `echidna`, `medusa`, `slither` or `certoraRun`**. Any workflow that targets repos 2-7 must provision Foundry itself (and, for olympus-v3, exactly v1.5.1). All 7 need outbound network for dependency resolution; 5 of 7 need an archive RPC for their fork lane.

| repo | canonical build cmd | canonical test cmd | fork-test entry point | what blocks offline execution |
|---|---|---|---|---|
| 1inch-lop | `yarn && yarn hardhat compile` | `yarn test:ci` (= `hardhat test`) | none in tests; the deploy path validates `MAINNET_RPC_URL` when `OPS_NETWORK=hardhat` | `yarn install`; hardhat downloads solc 0.8.30 (plus zksync compilers). Fully offline once `node_modules` and solc are cached. Best offline candidate. |

Practical takeaways for designing the workflows:

- **Deterministic PoC harness quality, best to worst:** spark-alm (fork block pinned in an overridable `_getBlock()`, and an exploit-style test already exists: `ERC4626DonationAttack.t.sol`) > olympus-v3 (`vm.createSelectFork("mainnet", 20900000)` at 82 sites; the `Fork` contract-name convention makes selection trivial) > lido-core (`FORKING_BLOCK_NUMBER` env) > aave-v3-origin (no fork tests at all, but by far the strongest invariant / echidna / medusa / certora harness) > arb-token-bridge (`SHOULD_FORK` boolean, unpinned block) > 1inch-lop and sky-dss (no chain forking anywhere).
- **In-repo address pinning:** lido (`deployed-mainnet.json`), 1inch (`deployments/<net>/*.json`), arb (`deployment-4216*.json`, `_deployments/*_current_deployment.json`), olympus (`src/proposals/addresses.json`, `deployments/mainnet-*.json`), spark (`script/input/1/*.json` plus `spark-address-registry` plus the live chainlog). **aave-v3-origin and sky-dss ship none** - an external address book is required for those.
- **Offline-first lanes worth targeting:** 1inch (everything), aave (everything incl. invariants), lido `yarn test:forge`, arb `forge test`, spark `test/unit/**`, sky-dss (once solc 0.6.12 is vendored). Everything else needs RPC credentials.
- **Dependency-fetch cost is the main automation tax:** olympus-v3 (soldeer plus the chainlink monorepo, and the chicken-and-egg of `forge` being required before `pnpm install`) and spark-alm (18 recursive submodules) dominate; pre-baked images or `--filter=blob:none` / sparse checkouts pay for themselves (olympus `audit/` alone is 110 MB).
- **Version pins to bake into an image:** foundry 1.5.1 (olympus); node 24 (olympus) and 22 (aave, lido); yarn 4.9.2 via corepack (lido); pnpm 11.13.0 (olympus); solc 0.4.24 / 0.6.11 / 0.6.12 / 0.8.9 / 0.8.25 (lido), 0.6.11 + 0.8.16 (arb), 0.8.15 + 0.8.24 (olympus), 0.8.25 (spark), 0.8.27 (aave), 0.8.30 (1inch), 0.6.12 (sky-dss).
